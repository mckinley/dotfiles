# dotfiles

Bronson's dotfiles: the shell, git and tool-version config for his macOS machines. They're managed by dtflmgmt (`mckinley/dtflmgmt`), the toolkit that tracks chosen home-directory files in git, installs them on a new computer (backing up whatever they replace), and reverts a borrowed computer afterwards. **This repo is public.**

## Why this file is AGENTS.md, not CLAUDE.md

This repo's work tree is the home directory, so every file in it is installed into `~`.

- A `CLAUDE.md` here would become `~/CLAUDE.md`. Claude Code loads that file into every session started anywhere under the home directory.
- A `.claude/CLAUDE.md` here would overwrite the user's global Claude instructions.

Keep agent context in this file, and never add `CLAUDE.md` or anything under `.claude/` to this repo.

## How it's installed and used (dtflmgmt)

- dtflmgmt's `install.sh` clones this repo into a temporary directory, with `--separate-git-dir` pointing at `~/.dotfiles/git`. It sets `status.showUntrackedFiles no`, then rsyncs the files into `~`, saving every file it replaces under `~/.dotfiles/backups/<timestamp>/`. dtflmgmt's `revert.sh` restores the most recent backup.
- After that, the home directory is the work tree. `.zshrc` defines `dotfiles` (alias `dot`) as `git --git-dir=$HOME/.dotfiles/git --work-tree=$HOME`. Use `dot status`, `dot add ~/.somefile`, `dot commit` and `dot push`, then run `dot pull` on the other machines.
- Only files added with `dot add` are tracked, and untracked files in `~` never show up in `dot status`.
- A normal clone, like one used for a pull request, works too: files sit at the repo root, exactly where they go in `~`.

## What's tracked

- `.zshrc`:
  - Oh My Zsh with the `asdf`, `autojump` and `git` plugins.
  - powerlevel10k, sourced from `~/.powerlevel10k` with `ZSH_THEME=""`.
  - direnv hooks and VS Code shell integration.
  - The `dot` aliases.
  - It sources `~/.zshrc.local` last.
- `.zprofile`: Homebrew `shellenv`, plus Homebrew Ruby on `PATH`.
- `.p10k.zsh`: the powerlevel10k prompt config. It was generated by the p10k configuration wizard, so re-run `p10k configure` rather than hand-editing it.
- `.gitconfig`: aliases, rebase on pull, `push.default current`, a VS Code difftool, git-lfs, rewriting `https://github.com/` URLs to SSH, and a GitHub noreply identity.
- `.gitignore_global`: global excludes (`.DS_Store`, `*~`, `*.local*`).
- `.tool-versions`: global asdf versions (nodejs, python, ruby, bun).
- `.editorconfig`: UTF-8, LF line endings, 2-space indent.
- `.dotfiles-provision.sh`: one-time machine setup. It installs Xcode CLT, Homebrew, CLI tools, the asdf plugins and the versions in `.tool-versions`, Oh My Zsh, and powerlevel10k with its fonts. It also installs the Chrome, Rectangle and VS Code casks, then switches the login shell to zsh.

Oh My Zsh and powerlevel10k themselves (`~/.oh-my-zsh`, `~/.powerlevel10k`) are installed by the provision script. They aren't tracked here.

## Checking a change

There's no build, test suite or CI. Before committing, run:

- `zsh -n .zshrc`, `zsh -n .zprofile` and `zsh -n .p10k.zsh`: syntax checks
- `bash -n .dotfiles-provision.sh`: syntax check
- `git config -f .gitconfig --list`: confirms the git config parses

## Rules

- **Public repo.** Never commit secrets, tokens, SSH keys, credentials, personal email addresses, hostnames or anything specific to one machine.
- **Local config stays local.** Machine-specific or private settings go in `~/.zshrc.local` (sourced at the end of `.zshrc`) or other `*.local*` files. Those are never tracked, and `.gitignore_global` ignores `*.local*` in every repo.
- **Add single files on purpose.** Never `dot add` a directory such as `~/.ssh`, `~/.aws`, `~/.config` or `~/.claude`.
- **Keep paths relative to `$HOME`** so the files work for any username. The known exception is `core.excludesfile` in `.gitconfig`, which is still an absolute path.
- **Don't move `~/.dotfiles/git`.** The `dot` alias and dtflmgmt's scripts all assume that location.
- **Every `.tool-versions` entry must also be a Homebrew name.** The provision script runs `brew install` and `asdf plugin add` on each entry, so the name must work as a Homebrew formula (or alias) and as an asdf plugin.
- **Known broken step:** `.dotfiles-provision.sh` installs `openssl@1.1`, which Homebrew has removed, so that `brew install` line fails as written.
